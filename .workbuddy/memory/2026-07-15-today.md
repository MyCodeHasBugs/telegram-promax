## 本轮实际改动 (server_v2.py, 纯服务器侧)

### F4-3 (a) 每 /24 子网连接配额 — 防单攻击者独占 200 槽位
- 新增 `MAX_CONN_PER_SUBNET = 8` (IPv6 取 /64 前缀).
- 新增 `_subnet_conn_count: dict[str,int]` 与 `_conn_subnet: dict[str,str]`, **全内存态**,
  断连即 pop, 完全不落盘 IP 字符串, 与"三不原则"兼容.
- `_subnet_24(remote)` 工具函数: IPv4 → `a.b.c.0/24`, IPv6 → `xxxx:xxxx:xxxx:xxxx::/64`,
  异常 → `0.0.0.0/24`. 6 个 sanity assert 全过.
- connect handler 顺序:
  1. 先查 MAX_CLIENTS / sio.environ 全局 (已有)
  2. 再查 `_subnet_conn_count[subnet] >= 8`, 超额 return False
  3. gate_token 不通过直接 return (不占subnet槽, 防扫描器占合法子网)
  4. 通过后才写 `_conn_subnet[sid] = subnet` 并 `_subnet_conn_count[subnet] += 1`
- disconnect handler 回填: `_conn_subnet.pop(sid)` 后 `--count`, count<=0 pop key.
- 单攻击者只能占单 /24 的 8 槽 → 独占 200 不再可能 → F4-3 (a) "占满槽位拒绝合法用户"
  缓解. NAT/CGNAT 下合法多用户同 /24 仍可连 8 个.

### F4-3 (b) relay_slice 会话级字节硬上限 — 防 200×500×1MB 放大
- 新增 `RATE_LIMIT_SLICE_BYTES = 256KB / 5s`.
- 新增 `rate_log_slice_bytes: dict[str, list[(int,float)]]` 与 `rate_log_slices` 同窗.
- 双 QoS: 旧条数 100/5s + 新字节 256KB/5s 任一超额即 rate_limit.
- 字节越上限额外 kick + disconnect (视为野攻击流).
- **关键修复**: 把原 `await sio.emit(...)` 从 `with _lock:` 里抽出. 之前在
  threading.RLock 内 await 阻塞 event loop 是反 async 模式 (即便巧合运行也可能是
  bug 来源). 新代码只在锁内做"是否超额"的判定与计数写入, emit 在锁外.

### disconnect cleanup
- 同步清掉 `rate_log_slice_bytes[sid]` 与已有的 `_connect_times` / rate_log 等,
  防 stale 计数泄漏.
