## 2026-07-14 下午 — 安全审计（可被黑客利用的 bug）
发现 1 个 CRITICAL + 2 个 HIGH，写入 `/e/launcher/security_analysis.md`：
- 🔴 CRITICAL: X25519 `ComputeSharedSecret` 未校验对端公钥是否为曲线上的点/低阶点。
  攻击者在 `auth.epub` 或 `envelope.dh_pub` 放入已知 8 阶低阶点 → 共享密钥只落 8 个可枚举值 →
  同房间任意成员可完整破解他人棘轮（无需 MITM、无需破密钥）。入口：RegisterPeer(.cs:179)、
  DoubleRatchet.TryRecv(.cs:358)。修复：换 NSec/libsodium 或加曲线点校验 + 拒绝 shared=0/低阶。
- 🟠 HIGH: 默认 ws 明文；客户端 `AllowSelfSigned=true` 默认放行任意证书，`ServerCertSha256`
  指纹锁默认不生效 → 中间人/元数据泄露，且无 epub↔id 绑定。
- 🟠 HIGH: `relay_slice/relay_message` 的 target 只查 `target in sessions` 不查房间归属 →
  跨房间投递，配合上面的低阶点攻击可跨房间命中。修复：target 必须在发送者房间内。
- 之前评估给"加密原语 9/10"偏乐观——核心缺失是**输入校验**，非原语本身。
  下一步优先级应改为：① 修低阶点校验 ② 服务器按房间校验 target ③ 默认 wss+证书校验。

新发现/仍存在的问题：
- F1 HIGH: `MainWindow.xaml.cs:68-71` 勾选 TLS 反而设 `AllowSelfSigned=true` → 加密无认证，可被 MITM；严格指纹锁在 GUI 无入口。
- F2 HIGH(架构): 缺"身份↔握手"绑定（Ed25519 `id` 自证、服务器不绑 `id`↔`epub`）+ 默认无 TLS → 网络中间人可不破密钥击穿 E2E 保密/真实。根因。
- F3 MED: `n`/`dh_pub` 未纳入 Ed25519 签名 → 主动攻击改写 `dh_pub` 使棘轮永久失同步(DoS)。
- F4 MED: Reassembler `Parts=new byte[total][]` 按 total(≤65535) 预分配，单条占~524KB，256 条未收齐≈128MB 内存 DoS。
- F5 LOW: `int.Parse(PortBox)` 无保护，本地坏输入崩客户端。F6 LOW: TLS 私钥明文落盘+10年。F7 LOW: `auth` 的 `b3` 校验可选。
结论：原语扎实，漏洞全在"密钥交换未认证"这一根因；先治 F1+F2(默认 wss+指纹锁+握手签名绑 id↔epub)。
